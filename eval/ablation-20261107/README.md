## 怎么读这份矩阵（如实声明）

1. **七组数字全同是预期结论，不是跑挂了。** 被测管线是 `RulesPipeline`（②段负面清单
   全量确定性扫描的独立基线），它不经过检索段与生成段——六组开关的 `@gated` 观测点
   都在那条链路上（`app/pipeline.py`），所以对本基线零影响。这正是 README 结构性判断①
   的量化印证：**②段命中不依赖检索/生成模块，消融它们不改变负面扫描结果**。
   带差异的消融矩阵需完整系统管线贯通后重跑同一条命令。
2. **匹配 53.52%／召回 15.38%** 与合并台账 #44/#46 对同一份数据（词典 81 词／25 组现行态）
   的独立实测逐字一致——本次为可复现性再确认。本次跑批加载：规则库全量 2044 条、
   现行规则集 1809 条（`active_records` 口径）、参与匹配 1797 条（matcher 口径）、
   词典 81 词/25 概念组；召回 micro 分母 130 条标注 refs。
3. **引用错误率 N/A**：runner 的 registry 核验要求列表元素含 `ref_id` 键，
   数据仓 `registry.json` 以 `文号` 为字段——现状下无法直接喂入（口径处理见"待办"）。
   按 `metrics.py` 纪律不默认引用为对，故记 N/A；本管线引用全部来自规则库出处字段
   （溯源 registry），非 LLM 手打。
4. **姿态违规 0**；数据侧 142 行＝120 正例（全 ref-level）＋22 条负对照（N1–N4），
   **负对照误报 0/22**（与 #44 台账 0/22 一致）。
