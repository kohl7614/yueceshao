## 1 软件概述

粤策哨是面向粤东西北县域强村公司与合作社的**申报前自查辅助工具**（静态演示
版参见 `docs/index.html`）。用户把帮扶项目描述（简介、资金用途、建设内容）粘贴
到输入框，系统输出一份四段式自查报告：① 适用政策清单 → ② 负面清单命中提示 →
③ 材料缺项清单 → ④ 修改建议。

软件的定位是**提示依据与风险，不作判定**：报告中的时效标签、命中级别、触发词
高亮都是「提示」，最终以政策法规原文及主管部门意见为准。报告末尾固定展示
免责声明与 AI 生成标识行（对应前端 `index.html` 页脚 `disclaimer-bar`、
`app.js` 第 448–465 行的报告尾部）。

## 3 三种使用方式

### 3.1 Web 在线体检（真实分析）

适用于任意项目描述（非预置案例）。流程（`docs/js/app.js` 的 `submitOnlineCheck` /
`startPolling` / `renderOnlineReport`）：

1. 在「项目描述」输入框粘贴描述，点击 **开始体检**；输入长度须在 20–2000 字之间
   （与后端 `app/main.py` 的 `CheckupRequest` 校验一致，过短/过长均给出提示）。
2. 系统 `POST /api/checkup` 提交，服务端返回 **202** 与 `task_id`、`poll_url`、
   `estimated_seconds`。页面显示「在线体检 · 真实分析 · 排队中」，`app.js` 如实
   展示 `queued`（排队中）/ `running`（分析中），不伪装进度百分比。
3. 前端每 **5 秒**轮询一次 `poll_url`（客户端上限 15 分钟）；任务完成（`done`）
   后把服务端 `result.rendered_text` **原样**放入等宽报告区展示，不增删改、不美化。
4. 任务失败或轮询到 404（任务不存在/已过期，保留 1 小时）时，页面如实展示原因
   并提供「重新提交」按钮。

### 3.2 Web 离线演示（预置案例）

适用于页面内置的典型案例（改编自审计公告真实条目）。流程（`docs/js/app.js`
的 `findMatchedCase` / `playAnalyze` / `showReport`）：

1. 点击页面下方「典型案例」中的任一卡片，卡片会把完整项目描述填入输入框；
2. 点击 **开始体检**，页面播放一段**演示动画**（解析 → 扫描政策语料库 → 负面
   清单比对 → 汇总，约 2 秒），动画页面明确标注「演示流程示意 · 本页为静态
   预置输出，非真实推理」；
3. 动画结束后展示该预置案例的内置四段式报告；报告头部折叠区标注「生成方式：
   静态预置输出（本页内置，无模型推理）」。此模式**内容不出本机**，也不需要
   后端服务。

> 输入若不匹配预置案例，会走 3.1 的在线体检路径；在线服务不可用时页面提示
> 「无法连接体检服务」，此时可用预置案例离线查看。

### 3.3 HTTP API（供第三方/小程序调用）

服务提供三个端点（`app/main.py`）：

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/checkup` | POST | 提交 `{"description": "..."}`，成功返回 202 + `task_id` + `poll_url` + `estimated_seconds`；超频返回 429 |
| `/api/tasks/{task_id}` | GET | 轮询状态：`queued`/`running`/`done`/`failed`；`done` 时 `result` 携带 `report`、`rendered_text`、`degraded`、`attempts`、`failed_sections`、`disclaimer`、`ai_generated` |
| `/health` | GET | 存活检查与管线装配事实 |

`description` 校验：去空白后 20–2000 字，空/过短/过长返回 422 并给出原因。
限流：每 IP 默认 **5 次/小时**（令牌桶，见 `app/ratelimit.py`），超频返回 429
并带 `Retry-After` 回满秒数。服务单 worker 串行执行，任务保留 **1 小时**，重启
会清空任务表（轮询 404 后重新提交）。

一次完整调用的示例（提交 → 轮询 → 报告）：

```bash
# 1) 提交体检任务（202）
curl -s -X POST http://127.0.0.1:8000/api/checkup \
  -H 'Content-Type: application/json' \
  -d '{"description":"我是某县某村人居环境整治项目的申报人，拟申请省级涉农资金260万元新建农村公厕8座并改造农户户厕60户，资金主要用于土建、化粪池及管网、设备购置，计划批复后第二年陆续实施。"}'
# 返回示例：{"task_id":"a1b2c3d4e5f6","status":"queued",
#            "poll_url":"/api/tasks/a1b2c3d4e5f6","estimated_seconds":5}

# 2) 轮询任务状态（每 5 秒一次，done 后取报告）
curl -s http://127.0.0.1:8000/api/tasks/a1b2c3d4e5f6
# done 时 result.rendered_text 即完整四段式报告文本（含 AI 标识行与免责声明）
```

> 报告中 `ai_generated: true` 为**隐式标识**（机器可读，符合《人工智能生成合成
> 内容标识办法》2025-09-01 施行要求）；显式标识行「AI 生成标识：本报告由人工
> 智能自动生成，仅供参考。」由服务端插入在免责声明之前，免责声明保持末行。

## 4 报告怎么读

四段含义（对应 `docs/index.html` 的「四段式报告 · 怎么看」）：

1. **适用政策清单**：可能相关的政策文件与条款，每条带时效标签——
   `现行有效`（仍在执行）、`申报已截止`（受理窗口已过，仅作参考）、
   `已失效供参考`（历史口径）。
2. **负面清单命中提示**：分「规则命中」（明确落入现行规定）与「疑似命中」
   （建议对照原文）两级。每条左侧为材料原文命中句、右侧为条款原文摘录，
   两栏并排；**规则命中**会高亮触发词，并附依据文号、条款号与日期；
   **疑似命中**无字眼级定位，不高亮。知识库未收录对应文号时不硬判、不编造。
3. **材料缺项清单**：对照第①段命中的现行政策，提示建议核对、补齐的申报材料
   （提示性质，不替代正式申报清单）。
4. **修改建议**：申报表述层面的改进建议，口吻为「建议」而非「判定」。

**置信与降级**：报告用确定性信号区分命中级别（规则命中 / 疑似命中），不由模型
自评置信度。若生成过程发生降级（如 JSON 解析失败后重试或用兜底），`result`
中的 `degraded=true`、`attempts`（重试次数）、`failed_sections`（降级段落）会
如实记录；页面仍展示报告，但读者应注意这些标记。

**「未命中」的含义**：②段显示无命中，只表示在现有政策库与负面清单下未检出
提示，**不代表**申报合规或一定获批——这正是系统不输出结论性措辞的原因。

**AI 生成标识与免责声明**：报告尾部固定两行——AI 生成标识行与免责声明；前端
渲染时不得隐藏、删改或美化。免责声明全文：「本报告仅为申报前自查辅助参考，
不构成合规判定，请以政策法规原文及主管部门意见为准。」

## 5 常见问题

| 问题 | 说明 | 出处 |
|---|---|---|
| 为什么提示「提交过于频繁」？ | 每 IP 每小时限 5 次（令牌桶），回满秒数见 429 响应的 `Retry-After` 头 | `app/ratelimit.py`、`app/main.py` |
| 为什么任务提示「不存在或已过期」？ | 任务仅保留 1 小时，服务重启也会清空任务表；请重新提交 | `app/tasks.py` |
| 一次分析要多久？ | dev 机单次体检端到端实测约 247–252 秒（约 4 分钟），服务器以落位后实测为准；`estimated_seconds` 仅为 UX 提示值 | `docs/部署指南-20261121.md` §5 |
| 为什么输入被拒收？ | 项目描述去空白后须 20–2000 字；过短/过长均提示具体字数 | `app/main.py`、`docs/js/app.js` |
| 为什么报告尾部有「AI 生成标识」？ | 依《人工智能生成合成内容标识办法》（2025-09-01 施行），显式行由服务端注入，隐式字段 `ai_generated=true` | `app/main.py` |
| 断网能用吗？ | 预置案例的离线演示可断网使用；在线体检需连接体检服务 | `docs/web-README.md` |
| 报告说「未命中」，是不是就能报？ | 不是。工具只做申报前自查提示，不构成合规判定，请以政策原文与主管部门意见为准 | `docs/index.html` 免责声明 |
