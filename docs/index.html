四段式报告 · 怎么看

报告由四段组成，越往下越接近「动手改」；颜色标签代表风险等级，不是结论。

  • 1

    适用政策清单

    列出与你的项目主题可能相关的政策文件与条款。每个文件带时效标签：现行有效（还在执行）、申报已截止（受理窗口已过，仅作后续批次参考）、已失效供参考（历史口径）。

  • 2

    负面清单命中提示

    对照政策红线，标出可能踩到的地方，分两级：规则命中（明确落入现行规定）与 疑似命中（建议对照原文）。每条都附依据文号、条款号、日期与原文摘录。

  • 3

    材料缺项清单

    对照第①段命中的现行政策，提示你申报时建议核对、补齐的材料（提示性质，不替代正式申报清单）。

  • 4

    修改建议

    在表述层面给改进建议，口吻是「建议」而非「判定」。你不一定要照做，但能少走弯路。

标签含义

规则命中 明确踩到现行规定，附依据文号、条款号与原文摘录。

疑似命中 建议对照原文确认；知识库暂未收录对应文号时，不硬判、不编造。

为什么只给提示、不给「合规 / 可以申报」结论？最终以政策法规原文及主管部门意见为准，本工具仅做申报前自查辅助。静态演示版仅内置 3 个典型案例的报告，真人系统为「输入即出」。

系统评测 · 三项指标与消融对比

三项指标衡量「体检报告可不可信」：匹配率看判定对不对，召回率看该查到的条款有没有漏，引用错误率看文号可不可核验。指标口径与验收线来自团队手册 3.4（实现见 eval/metrics.py）；完整系统（基线）与消融组的对比矩阵由 eval/runner.py 跑批产出。真实生成管线尚未接入，数字一律诚实标注 N/A、待跑批后回填，不预填任何预估数字。

  • 匹配率 验收线 ≥ 85%

    系统判定（命中 / 未命中负面清单）与人工标注判定的一致率。分母只计已标注判定的案例，未标注的进逐案例明细、不参与该指标。

数字从哪里来 · 如何复算

接上真实管线后，跑批命令（在仓库根目录执行）：

python -m eval.runner --cases <数据仓>/审计公告/案例标注表.csv --registry <registry 导出>.json --ablate-all --out runs/ablation
  • 案例标注表（120 条）在团队数据仓、不随仓库分发：审计公告是评测出题集，进检索索引＝答案泄露（开发红线第 4 条）；
  • 当前 eval/pipeline.py 为占位实现（NullPipeline），跑批数字没有实验意义——本区块因此诚实标注 N/A：绝不拿 0 或 1 冒充，也不预填预估数字；
  • 有 N/A 项时 all_pass 为 false：不能靠缺失项过关；
  • 口径细节见 eval/README.md 与 eval/metrics.py；跑批产物 metrics.json / ablation_matrix.csv 即本区块的数字来源，跑完即回填。
