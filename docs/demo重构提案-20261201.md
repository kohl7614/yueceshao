## 一、诊断确认

§二 六条逐一确认：

1. **两类读者混排** ✓ 确认。hero 输入区 / 预置卡片 / howto / eval / 报告在同一长页。
2. **最硬成果埋没** ✓ 确认。匹配 97.78% / 召回 95.65% / 引用错误 0.00% 在页面中部 eval 区。
3. **消融矩阵需分层** ✓ 确认。七组矩阵对普通访客噪音。
4. **w/o:rule_scan 误读** ✓ 确认。1/3 达标易被误读为缺陷；实为规则扫描模块价值证明（关闭确定性扫描后召回 95.65%→0%）。
5. **howto 过长** ✓ 确认。四段解读独立大区块打断主线。
6. **合规元素散布** ✓ 确认。免责声明在 footer；AI 行在 hero-sub/analyze-note/howto-note；双模式流向在 form-hint。

补充问题：

- B. report-wrap 与 presets 顺序：报告在 eval 之后、数据来源之前，长页滚动链路过长。
- C. 移动端三档适配（375/768/1280）尚未在 proposal 中明确——建议与 IA 一并定义断点。

## 二、信息架构方案

手法：Tab 二级视图 + 折叠 + 锚点。

顶层 Tab：「体检工具」（默认） / 「评测成果」 / 「方法说明」。

结构（自上而下）：

屏 1（所有 Tab 共用顶栏）：header + Tab 导航 + 合规 AI 行（小字）。
Tab「体检工具」：
- 屏 2：hero 输入区（含三指标摘要卡，前置）+ 双模式说明（折叠）
- 屏 3：典型案例卡片
- 屏 4：体检过程（动画，仅离线）
- 屏 5：报告区（内联 howto 提示折叠）
- 屏 6：免责声明 footer（全 Tab 固定）

Tab「评测成果」：
- 屏 2：三指标大字卡（97.78 / 95.65 / 0.00）+ 验收线
- 屏 3：消融矩阵（默认收起，点开；含 w/o:rule_scan 结论标注）
- 屏 4：数字来源 details（原 eval-details）

Tab「方法说明」：
- 屏 2：howto 四段（压缩为可折叠列表）
- 屏 3：数据来源说明
- 屏 4：评测口径链接

## 三、首屏线框

1280：左 60% 输入区 + 右 40% 三指标摘要卡（匹配/召回/引用错误）+ Tab；三指标前置在首屏右栏。

375：单列，三指标摘要卡横排（3 列小卡）置于 hero 输入区下方；Tab 横向滚动。

## 四、消融矩阵呈现方案

默认态：仅显示「完整系统（基线）」一行 + 「展开查看 6 组消融对比」按钮。

展开态：完整 7 行表；w/o:rule_scan 行高亮背景并附结论标注。

「怎么读」引导文案草案：
> 每行移除一个模块，对比三指标变化。数字不变的模块 = 对本评测集非关键；数字骤降的模块 = 生命线。

w/o:rule_scan 结论标注文案草案：
> ⚠ 该行是「规则扫描模块价值的量化证明」：关闭确定性扫描后，召回率 95.65% → 0.00%，证明规则引擎是②段负面清单命中的生命线，LLM 蕴含仅作二次确认。产品形态 = 基线行（3/3 达标），本行仅为受控实验对照，不代表产品缺陷。

## 五、打磨四件共存方案

1. 移动端三档（375/768/1280）：CSS 断点；Tab 在 375 横滚；矩阵在 375 卡片化。
