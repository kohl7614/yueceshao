## 0. 问题陈述（三个事实，全部已在 main 现状核实）

1. `eval/runner.py` 的 `--ablate` 只翻转 `AblationSwitches` 布尔位并包一层 `ablation_context`，
   但 `eval/real_pipeline.py` 的 `predict()` 直接调 `RealCheckupPipeline.run()`，**全链路不读开关**；
2. `app/real_components.py` 真实管线只有：稠密检索（Chroma＋时效 where）、规则全量扫描、
   LLM 蕴含复核、生成、确定性校验——**没有 BM25 混合、没有 Cross-Encoder 重排、
   没有"命中即中断生成"动作**（`rag/rerank.py` 模块存在但管线未接线）；
3. 结论：六开关里 `rerank`／`hybrid_retrieval`／`negative_hard_constraint` 在真实管线中
   **无对应模块**，`--ablate-all` 跑真实管线必然 7 组同数字＝假消融。

## 1. 新开关清单（6 开关 → 1 完整系统＋6 消融＝7 组矩阵，组数不变）

| 开关名 | 对应真实模块（现实现） | 接线点 | 关闭后预测行为变化 | 观测点（测试断言） |
|---|---|---|---|---|
| `temporal_filter` | DenseRetriever 的 `is_current` where 前置过滤（A6，现配置项） | `RealComponents` 持双检索器（同一 embedder/backend，`enable_temporal_filter` 一真一假），按开关选用 | 已废止条款可能进①段上下文/引用；②段 refs 不变（规则库本身只取现行口径） | 时效关 → `_retriever_plain` 被调用（注入双 fake 断言选用）；真装配时 `RetrievalResult.where` 不含 `is_current`（复用 rag 既有测试口径） |
| `dense_retrieval`（新） | 稠密检索调用（embedding 编码＋Chroma 查询） | `_dense_retrieve` 套 `@gated("dense_retrieval", stage="retrieve.dense", fallback=空 RetrievalResult)` | **稠密调用真跳过**（不编码不查库）；①段上下文仅剩规则命中块；②段引用仍可解析（规则块保留在 hits）→ 三指标不变，`rendered_text` ①③④段退化、可能"未覆盖" | 假 retriever 调用次数=0；plan.hits 无 `origin=retrieval` 块；trace 记 bypass |
| `rule_scan`（新） | `NegRuleMatcher.match` 全量确定性扫描（②段规则路） | `_rule_match` 套 `@gated("rule_scan", stage="rules.scan", fallback=空 MatchResult)` | ②段规则命中消失，仅剩 LLM 蕴含疑似命中 → verdict 可能 miss、recall 下降 | 假 matcher 调用次数=0；report②段无"规则命中"行；trace |
| `entail_review`（新） | LLM 蕴含复核（G01-G11 载体，qwen/Mock） | `_entail` 套 `@gated("entail_review", stage="entail.review", fallback="[]")` | 疑似命中消失，②段仅规则命中；LLM 蕴含调用 0 次 | 假 llm.entail_review 计数=0；trace |
| `query_decomposition`（保留原名） | extract 节点：LLM 结构化抽取（真实现，图 parse 节点） | extract 回调套 `@gated("query_decomposition", stage="parse.extract", fallback=合法空抽取 JSON)` | LLM 抽取 0 次；生成段 `extraction_json` 收空串（无术语归一化）→ ①③④段质量变化，三指标不变 | 假 llm.extract 计数=0；generate 收到空抽取；trace |
| `citation_validator`（保留原名） | `gen.validator.validate_all` 四类校验＋图级重试（A9，真实现） | `app/graph.py` 模块级 `gated("citation_validator", stage="validate.all", fallback=ValidationReport(passed=True, issues=()))(validate_all)`；`parse_generated` 结构解析与渲染层免责声明兜底**不关** | 坏标记/禁语不再被拦、不重试 → `degraded=False` 直接出报告；`metrics.forbidden_violations` 事后会抓到禁语（正是消融要展示的价值） | 构造含禁语的 mock 生成输出：off→文本含禁语且 degraded=False；on→被拦（重试/降级）；trace |

**与任务卡示例的两处偏差（如实声明）**：
- `gated` 不套在编排**回调**（`retrieve`/`rule_scan` 回调）上，而套在其背后的**模块执行函数**上。
  原因：②段引用解析依赖 hits 里保留规则块——若把 `retrieve` 回调直接短路成 `()`，
  标记表会整体丢失，②段引用全部变"依据标注缺失"，那是把"关检索"误伤成"关引用"的假消融；
- `query_decomposition` 不在新清单示例里，但 extract 节点**是真实现**，故保留并接线
  （删除它反而制造新的假缺口）。

## 3. 接线机制（三个文件的职责）

1. **`eval/gating.py`（最小扩展，向后兼容）**：`gated()` 新增可选参数
   `source: Callable[[], tuple[AblationSwitches, SwitchTrace] | None]`——提供时**显式**
   读取开关与 trace，优先于 contextvar；不提供时行为与 PR1 完全一致（旧测试零改动）。
   动机：LangGraph 并行分支（retrieve‖rule_scan）在独立线程执行，contextvar 是否继承
   无保证——评测口径不能建在"大概率能继承"上。
2. **`app/real_components.py`**：`RealComponents.set_ablation(switches, trace)`（实例级
   source 提供给 gated；`__init__` 里对三个执行函数做实例级包装）；temporal 双检索器；
   `RealCheckupPipeline.run()` 在 `graph.invoke` 外再显式 `with ablation_context(...)` 重进
   上下文（双保险，主线程直调路径也成立）。
3. **`eval/real_pipeline.py` + `eval/runner.py`**：`RealPipeline` 新增
   `configure(switches, trace)`；`runner.run_group` 进入 `ablation_context` 后
   `getattr(pipeline, "configure", None)` 存在即调用——**开关真正传进管线**（任务卡要求③），
   且 runner 与管线共享同一个 `SwitchTrace`，`result.trace` 汇总完整。
   `NullPipeline`/`RulesPipeline` 无 `configure` → 原路径不受影响。
