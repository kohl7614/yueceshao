# 索引重建（2026-11-07）

> 对应《开发手册 v1.0》§3.1 数据层；承接 #27 分块器修正。
> 本文只记录「为什么重建、用哪三样版本、怎么验收」。**索引本体不入库**（`.chroma/` 在 `.gitignore`）。

## 1. 为什么要重建

旧索引建于 2026-11-02 23:35，是 **#27 分块器修正之前**的产物：18262 块 / 717 篇。

#27 修了两个会「不报错但给错结果」的 bug——目录行被当成章标题、标题行把后续正文吞进来。
修正后切块数变为 20099，旧索引与 main 的代码不再同期，检索分数和 τ=0.55 都失去可比性。

> 判据澄清：任务书里写「若索引是 #23 修复前的旧版」并不准确。
> #23 是入库器**续跑**的内容指纹判定，不动切块；真正改变块数的是 **#27**。

## 3. 步骤

```bash
# 0. 前置统计：不写库，先确认 loader 口径与切块数（防止「跑完才发现不对」）
python frame_stats.py .

# 1. 冒烟：先在独立目录写 32 块，确认模型加载与写库链路
python -m rag.indexer --from-corpus --config config.smoke.json --limit 32 --check

# 2. 全量重建（resume 会按内容指纹跳过已入库块，中断可续）
python -m rag.indexer --from-corpus --config config.json --check

# 3. 验收
python -m scripts.verify_index --config config.json --expected-count 20099 --sample 10
```

`config.json` 里 `index.persist_dir` 用**绝对路径**。相对路径按运行命令时的**当前工作目录**解析，
指错目录时 Chroma 会静默建一个空集合、`count()` 读成 0，看起来像「索引是空的」。

## 5. 已知问题

**序号 162 的类别标错（判据盲区）。**
《关于2015年度审计查出突出问题整改情况的报告》在 registry 里 `类别 = 资金管理办法`，
但登载机关是省审计厅。`loader` 按 `category == 审计公告` 过滤，因此放它进了索引，本次切出 **49 块**。

它不在 14 篇审计公告出题集内，按红线④的**字面口径**不构成泄漏，`verify_index` 也判 0；
但这是**判据没覆盖到，不是数据安全的证明**。修正需数据负责人在语料仓改 registry 类别，
改后必须整库重建（块数会变 20050），故本次不阻塞，另开 issue 跟踪。

**序号 438 缺篇。** 文件名含竖线 `|`，Windows 无法落地，719 → 718 篇。平台限制，非代码问题。
