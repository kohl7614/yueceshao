> 目标：跑 `--pipeline real --ablate-all`，回填三指标（匹配 ≥85% / 召回 ≥80% /
> 引用错误 ≤5%）与 7 组消融矩阵，替换 demo 展示区块的 N/A。
> 本文是**分发规范**：区间怎么切、每人要装什么、跑什么命令、交回什么、守什么铁律。

## 一、为什么三人分片

142 条案例 × 7 组消融 ≈ 990 次管线，每次 2–3 次 LLM 调用。三人分片用各自免费的
DashScope（qwen）额度，token 与耗时均摊。**LLM 走 qwen**（智谱的 5 亿额度只在
agent 内部、不能走 API，故不用 GLM）。

## 三、每人环境前置（5 样，缺一不可）

1. **代码仓**：`git clone https://github.com/kohl7614/yueceshao.git`（或 `git pull` 到最新 main）。
2. **数据仓**：clone 团队的 `yueceshao-data`（只读），案例标注表在 `审计公告/案例标注表.csv`。
3. **索引**：从 kelier1 分享的网盘链接下载索引 zip，解压到项目目录（如 `yueceshao/.chroma`）。
4. **embedding 模型**：`Qwen/Qwen3-Embedding-0.6B`（按 README 从 ModelScope 下载到本地，权重不入库）。
5. **qwen key**：见下节。

### qwen key 获取与额度

1. 登录 [阿里云百炼 DashScope](https://dashscope.aliyun.com) → API-KEY 管理 → 创建 key。
2. 写进自己机器 `.env`（gitignored）：`DASHSCOPE_API_KEY=<你的 key>`。
3. **查额度**：控制台「用量/额度」确认免费额度 ≥ **200 万 token**（每人约需 200 万）。
   不够就充值（qwen-max 约 input ¥0.02/千 + output ¥0.06/千，200 万 token ≈ ¥40–80），
   **跑前先确认，避免跑到一半额度耗尽白跑**。

## 四、config.json 三处要改（复制 `config.example.json` 后）

```json
{
  "data_repo": "<你的数据仓绝对路径>",
  "index":   { "persist_dir": "<解压后的 .chroma 绝对路径>" },
  "embedding": { "model_dir": "<你的 Qwen3-Embedding-0.6B 绝对路径>" },
  "generation": { "model": "qwen-max", "api_key_env": "DASHSCOPE_API_KEY" }
}
```

## 五、跑批命令（照抄，只改区间）

```bash
python -m eval.runner \
  --cases <数据仓>/审计公告/案例标注表.csv \
  --registry eval/registry-export.json \
  --pipeline real --ablate-all \
  --offset <你的 offset> --limit <你的 limit> \
  --out runs/<你的名字>
```

`eval/registry-export.json` 已随仓库提供（条款级文号注册表，供引用错误率核验），
**三人必须用同一份**，合并时才能对账。

## 六、交回产物（三个文件，原样交回，不手改）

- `runs/<你的名字>/metrics.json`
- `runs/<你的名字>/group_details.csv`（合并的关键，勿删）
- `runs/<你的名字>/ablation_matrix.csv`

## 七、铁律（违规＝重跑）

1. **不编造数字**：指标如实输出，跑不动/额度不足就如实报失败，不预填、不手改产物。
2. **不提交 key、不 push 数据仓**；索引/模型/`.env` 不入库。
3. 生成调用一律 temperature=0（已在代码强制，config 不得覆盖）。
4. 拿不准就停下来问，不猜。

## 八、合并收口（负责人/主力会话做）

三份 `group_details.csv` 交齐后，用 `python -m eval.merge` 拼回全量、重算三指标与
消融矩阵（比率不能跨片简单平均），产物回填 demo 展示区块。
