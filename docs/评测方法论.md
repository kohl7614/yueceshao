# 评测方法论——为什么我们的评测可信

> 面向评审的一页说明。三项指标口径源自《粤策哨开发手册 v1.0》§3.4／§5，代码落点在
> `eval/metrics.py`（**口径定义不得随意改动**，改动需负责人批准——本文只描述、不修改）。
> 案例标注表与负对照存放在团队数据仓（不随代码入库），这个隔离本身就是可信性设计的一部分（见 §4）。

## 0. 我们承诺什么（口径与验收线）

| 指标 | 验收线（手册 3.4） | 操作化定义（`eval/metrics.py` 模块文档，逐条可复算） |
|---|---|---|
| 政策匹配准确率 match_rate | ≥85% | 判定一致率：系统 verdict（hit/miss）vs 标注 expected_verdict；分母只计已标注判定的案例，未标注的进明细单列 `verdict_unlabeled` |
| 违规情形预警召回率 recall | ≥80% | 正例条款召回，micro 口径 `Σ\|预测∩标注\| / Σ\|标注\|`；只标 hit 未给条款的退化为 case-level，并在明细 `recall_mode` 标注 |
| 条款引用错误率 citation_error_rate | ≤5% | 系统输出的每条引用须能在 registry（文号注册表）核验；未给 registry 时该指标为 **N/A**——无法判断真假时不默认它对。另单独统计姿态禁语违规数 |

基线＝通用大模型零样本提示；全部生成调用 **temperature=0**（§5）。无可计算样本时指标返回
None（报告显示 N/A），**绝不拿 0 或 1 冒充**——这条写在 `metrics.py` 的口径注释里，测试锁定。

## 1. 合规负对照：0 误报，且是"长出来"的防线

- **规模与战绩**：负对照住数据仓，N1–N4 四批次（判据文档 §4 的批次表：N1 8 条＋N2 10 条＋
  N3 2 条＝18 条起步；#44 后为 22 条）。合并台账实测记录：PR #41 时点 **0/18** 误报，
  PR #44 时点 **0/22** 误报——即"合规项目的正常描述"从不被规则引擎误判为负面命中。
- **写作纪律**（N1 起沿用，见 `docs/词典边界与判据.md` §4）：禁否定式（"不存在违规"会与触发词
  共现误报）、避开高权重触发词（补助/补贴/福利/奖金）、每条 150–300 字、要件可溯源、
  **复核人签字后才算生效**。
- **准入门**：任何扩词/收词 PR 必须附对应批次负对照 **0 误报实测证据**（判据文档明文纪律）。
- **回归守卫**：`tests/test_rules_lexicon.py` 把排除词（中性/否定式词）钉成测试，还原词典即转红。

## 2. 召回按"等价组全谱系"口径——但引用口径不跟着放松

审计公告案例多为历史项目，标注的期望条款常是**历史载体文号**；而规则引擎按设计只输出
**现行载体**——若按字符串精确匹配，召回会被"同一件事换了个文件号"系统性归零，那是评测失真，
不是系统失分。因此（`eval/rules_pipeline.py` 口径注释）：

- **refs（召回用）**＝直接命中条款＋其等价组全部成员（历史与现行）：语义是"条款族召回"，
  期望条款与命中条款同属一个等价组即计召回；
- **citations（引用错误率用）**＝仅直接命中：**引用错误率只算系统实际给出的引用，语义不变**。

等价组来自数据仓条款归并 json（`rules/schema.py` 的等价组索引，G01–G11 为省市县三级同构链），
口径固化在代码与测试里，不是每次跑批临时拍板。

## 3. 质量门 τ 的标定在仓内可复现

`docs/rag-rerank-标定.md`：40 条自建查询分 A（域内已覆盖 20）/B（近域 10）/C（完全域外 10）
三组实测——A 组下沿 0.605 与 C 组上沿 0.507 之间存在 0.098 空隙；0.525–0.600 为**零误拦平台区**；
**τ=0.55** 取平台区中部偏下（高于 C 上沿 0.043 留模型版本波动余量、低于 A 下沿 0.055 留表述
含糊余量）。可复现资产已入仓（`eval/calibration/`）：标定脚本＋A/B/C 三组查询文件，
`python -m eval.calibration.calibrate_rerank --config config.json` 即可复跑。
诚实边界（calibration README 明文）：**查询集可复现 ≠ 分数可复现**——逐位对齐需要与标定基线
一致的分块索引（718 篇／18262 块）；换索引必须重新标定，不许拿文档数字当预期。

## 4. 审计公告永远不进检索索引——评测题源与系统输入物理隔离

评测出题集＝审计公告 14 篇（数据仓）。若它们进了检索索引，等于把评测答案泄露给被评测系统，
所有指标作废。红线④由**三层拦截＋各有测试**保证：

| 层 | 机制 | 守卫测试 |
|---|---|---|
| 加载 | loader 按 registry 类别＝审计公告剔除（733→719 篇） | `tests/test_loader.py`（含"只看类别字段"用例） |
| 入库 | indexer 拒绝审计公告入库与编码；清出遗留块 | `tests/test_indexer.py` 红线④用例 |
| 检索 | retriever 默认 `exclude_categories:["审计公告"]`＋结果侧 `is_retrievable` 再挡（含缺 category 字段的旁路场景） | `tests/test_retriever.py` 红线④用例 |

评测侧只消费标注表 CSV 与 registry 元数据（`--registry` 传入），公告原文不进管线。

## 5. temperature=0 与确定性生成纪律

- `gen/prompts.py`：`GENERATION_TEMPERATURE = 0.0`，调用侧必须使用该常量（评测纪律，手册 §5）；
  `config.example.json` 的 `generation.temperature` 样例同为 0。
- LLM 永不手打文号：引用走 `[Cn]` 标记＋registry 元数据渲染，确定性校验器兜底
  （标记存在性/上下文包含性/姿态禁语/免责声明，重试≤2 后降级显式标注）——
  引用错误率统计的是**系统实际给出的引用**，没有"人肉修样本再算分"的空间。
- 置信标签由确定性信号驱动（规则命中/重排分/时效状态），不让 LLM 自评置信度。

## 6. 口径的已知限制（如实声明）

1. `--pipeline rules` 跑出的数字是**第②段规则引擎的独立基线**（相当于关掉 LLM 蕴含复核的
   消融视角），召回只会低于完整系统，不能替代完整管线的验收结论（`rules_pipeline.py` 文档注明）。
2. 标注表 120 条全为应命中正例、无负对照——该基线下匹配率/误报口径受限，误报面由独立的
   负对照线（§1）负责，两条线不混算。
3. 逐案例明细（`details.csv`）与 `metrics.json` 全量留档，任何人可用同一份数据仓文件重算
   三个数字；消融矩阵（`ablation_matrix.csv`）逐组记录关闭的开关与 trace 旁证。
