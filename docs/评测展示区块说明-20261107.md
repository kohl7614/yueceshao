# 评测展示区块说明（2026-11-07）

> 分支：`feat/demo-eval-page` · **AI 参与完成编码与验证，人工检查范围见 PR 描述**。
> 本文件随 PR 提交，供审阅对照与后续数字回填。

## 一、背景与定位

按组长任务，把评测三指标（匹配率 / 召回率 / 引用错误率）与「基线 vs 完整系统」消融对比做成静态展示区块，接在 demo「四段式报告 · 怎么看」之后，视觉沿用纸墨风。

## 二、区块内容（全部为仓库内可核验事实）

| 内容 | 来源 |
|---|---|
| 三指标口径（判定一致率 / micro 条款召回 / registry 引用核验） | `eval/metrics.py` docstring |
| 验收线：匹配 ≥85% / 召回 ≥80% / 引用错误 ≤5% | `eval/metrics.py::EvalThresholds`（手册 3.4） |
| 「完整系统＝六组开关全开（基线组）」与六个消融组名称、中文说明 | `eval/config.py`（`SWITCH_NAMES` / `SWITCH_DOCS` / `is_full_system`） |
| 姿态违规单独统计、免责声明先剔除再扫 | `eval/metrics.py`（`FORBIDDEN_PHRASES` / `strip_disclaimer`） |
| 复算命令、数据不入库红线、N/A 纪律 | `eval/README.md`、`eval/runner.py` |

## 三、关键取舍：数字一律 N/A，不预填

`eval/pipeline.py` 当前为占位实现（NullPipeline），`eval/README.md` 明示其跑批数字**没有实验意义**；`docs/AI协作流程.md` 全仓扫描也把「消融数字当前无意义」列为已知缺口。因此本区块遵循 eval 的 N/A 纪律（「不可计算的指标一律 None，绝不拿 0 或 1 冒充」）与 demo 红线（不得虚构）：**口径、验收线、矩阵结构全部为真，数字单元格一律 N/A ＋「待真实管线跑批回填」**。接上真实管线并跑批后，由 `metrics.json` / `ablation_matrix.csv` 回填本区块即可。
