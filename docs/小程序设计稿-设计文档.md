## 2 交互状态机（逐态对齐 Web 端 PR#104）

Web 端是权威（`docs/js/app.js` 的 `submitOnlineCheck` / `pollTaskStatus`），
小程序**逐态对齐同一语义**，不重新发明。参数：轮询每 **5 秒**一次、客户端
上限 **15 分钟**；输入 20–2000 字（strip 后计字）；提交 `POST /api/checkup`
返回 202＋`task_id`＋`poll_url`＋`estimated_seconds`；轮询 `GET poll_url`。

| # | 状态 | 触发 | UI 文案（逐字对齐 app.js） | meta | 按钮 |
|---|---|---|---|---|---|
| 1 | 输入校验 | 字数 <20 或 >2000 | `description 过短（至少 20 字），请按「简介＋资金用途＋建设内容」补全` / `description 过长（上限 2000 字）` | — | 禁用提交，提示补全 |
| 2 | 提交中 | 点击开始，POST 进行中 | `正在提交项目描述…` | `已等待 0 秒` | 无（禁用提交） |
| 3 | queued | 202 受理 / 轮询返回 queued | `排队中` | `已等待 N 秒` | 无 |
| 4 | running | 轮询返回 running | `分析中` | `已等待 N 秒` | 无 |
| 5 | done | 轮询返回 done | 切到报告页，`rendered_text` **原样渲染** | — | 报告页操作 |
| 6 | failed | 轮询返回 failed | `体检执行失败，请稍后重试`（或服务端 `error` 安全文案） | `任务编号 X` | 「重新提交」 |
| 7 | 404 过期 | 轮询 HTTP 404 | `任务不存在或已过期（保留 1 小时），请重新提交。` | `任务编号 X` | 「重新提交」 |
| 8 | 429 限流 | 提交 HTTP 429 | `提交过于频繁，请稍后再试。`＋`约 N 秒后可重试。`（读 `Retry-After` 头） | — | 「重新提交」 |
| 9 | 15 分钟超时 | 轮询达上限 | `分析时间较长，可稍后手动重试。` | `任务编号 X` | 「重新提交」 |
| 10 | 网络错误 | 提交 fetch 失败 | `无法连接体检服务（<API_BASE>）。请确认服务已启动；演示数据可用下方典型案例卡片离线查看。` | — | 「重新提交」 |
| 11* | 422 拒收 | 提交 HTTP 422 | `提交被拒收，请检查项目描述后重试。`（或服务端 detail） | — | 「重新提交」 |
| 12* | 轮询波动 | 轮询瞬时断连/非 200/解析失败 | `轮询连接波动，正在重试…` / `查询任务状态失败（HTTP N），正在重试…` / `任务状态响应无法解析，正在重试…` | — | 无（继续轮询至截止） |

> 说明：任务书表格要求覆盖 8 态（queued/running/done/failed/404/429/超时/网络错误），
> 本稿额外列出输入校验、提交中、422、轮询波动，是 Web 端实际存在的态，一并覆盖更完整。
> `*` 为超出任务书最低要求的补充态。

**状态机铁律**（与 Web 端完全一致）：
- queued 就写「排队中」，running 才写「分析中」——**不得把 queued 画成「分析完成」**；
- 服务端 `rendered_text` 已注入四段＋AI 标识行＋免责声明，前端**等宽原样渲染**，
  不隐藏、不删改、不美化；
- failed 展示安全文案，内部细节（路径/堆栈/key）只落服务端日志，不下发；
- 429 必须读 `Retry-After` 并在文案中给出等待秒数；
- 所有错误态提供「重新提交」，且按当前输入重新走一遍流程。

状态流转图：

```
[输入页] --校验通过--> 提交中 --202--> queued --> running --> done --> [报告页]
    ^                     |              |          |          |
    |                     v              v          v          v
    +----重新提交---- failed / 404 / 429 / 15分钟超时 / 网络错误
    ^
    +----离线案例卡片----> [报告页]（烘焙报告，无网络请求）
```

### 3.3 质感实现取舍（真机性能优先）

- **保留**：红头（顶部 6px 印章红实线）、朱砂印章方块「粤」、状态卡顶边红、免责声明红框
  （红框为法规级呈现，不可降级掉）——这些都是低开销的边框/背景色。
- **降级**：Web 端纸面纹理用 `repeating-linear-gradient` 纤维底纹，小程序端在
  iOS/Android 上大面积重复渐变可能影响滚动帧率——改为**纯 `--paper` 底色**，
  仅顶部光晕用一层静态背景图（或无，按真机实测决定）；不牺牲免责声明与印章识别度。
- **不用**：外部字体、外部图片资源（包体积与加载速度）；图标用 CSS 方块/文字符号。
- 窄屏并排对照（②段材料原文 vs 条款原文）在 375px 下改为**上下堆叠**
  （Web 端 `≤640px` 媒体查询同款：`grid-template-columns: 1fr`，中间连接符改 `↓`）。

## 5 小程序适配注意

1. **网络请求**：小程序用 `wx.request`，无同源策略、无 CORS 限制（与 Web 端不同，
   Web 端需 CORS 中间件）。`API_BASE` 为单点常量；将来连真实服务**只带 API_BASE 地址，
   包内不得出现任何 API key**（key 只在服务端）。
2. **合法域名**：开发期在微信开发者工具勾「不校验合法域名」联调；真机预览用局域网 IP
   填 `API_BASE`；上线前在小程序后台配置 request 合法域名（备案域名，阶段 B/R10）。
3. **包体积**：主包 ≤2MB。`data.js` 约 68KB，可整包携带（离线三案例必备）；
   截图类大图不入包。报告文本为纯文本，压缩比高。
4. **分享文案**：名称/简介/分享统一「**申报前自查辅助工具**」口径；避开时政政务
   敏感表述（路线图 R10：类目「工具-信息查询」，名称/简介避时政，影响提审通过率）。
   分享卡片不带报告正文、不带文号。
5. **免责声明法规级红线**：报告页 AI 生成标识行＋免责声明必须展示且不可隐藏
   （《人工智能生成合成内容标识办法》2025-09-01 施行，红线③）；小程序端不得以
   折叠、滚动折叠、样式隐藏等方式规避。
6. **交付边界**：本阶段只新增设计文档与单文件原型，不改后端、不改既有 docs 页面、
   不碰数据仓；阶段 B 的 uni-app 工程（`miniprogram/` 子目录、测试号联调、正式 AppID
   与提审）在验收后另发确认。
