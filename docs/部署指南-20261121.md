## 1 落位清单（什么走什么通道）

| 产物 | 通道 | 红线依据 |
|---|---|---|
| 代码 | `git clone https://github.com/kohl7614/yueceshao.git`（main） | 代码入公开仓 |
| 索引（20099 块） | **rsync/scp 直传** dev 机 `.chroma/` → 服务器 `/opt/yueceshao/yueceshao/.chroma/` | 索引/语料不入任何 git 仓 |
| embedding 模型 | ModelScope 下载 `Qwen/Qwen3-Embedding-0.6B` → `/opt/yueceshao/models/Qwen3-Embedding-0.6B`（或与索引同批 rsync，dev 机已在 `yueceshao-real-adapter/models/`） | 权重不入 git |
| reranker 模型 | HF 下载 `BAAI/bge-reranker-v2-m3` → `/opt/yueceshao/yueceshao/models/bge-reranker-v2-m3`（约 2.1G） | 权重不入 git |
| API key | `/etc/yueceshao/yueceshao.env`（root:0600，**仓库外**）：`DASHSCOPE_API_KEY=…` | key 永不入库不入端 |
| 数据仓 | 服务器**不需要** clone 数据仓？——需要：规则库（条款归并 json）与 config 路径经 `config.json` 的 `data_repo` 相对路径读取。方案：`git clone https://github.com/kohl7614/yueceshao-data.git`（私有仓，只读）到 `/opt/yueceshao/yueceshao-data`，与代码仓并排（与 dev 机同布局）；**禁止在服务器上 push 数据仓** | 数据仓 push 只由负责人会话执行 |
| config.json | 复制 `config.example.json` 改：`data_repo: ../yueceshao-data`、`index.persist_dir: .chroma`、模型两段路径；**config.json 不入库**（.gitignore 已排除） | 真实配置不入库 |

## 2 服务器五样前置机械核验（分发文档 §三同款，逐条执行）

1. 代码基线：`git -C /opt/yueceshao/yueceshao merge-base --is-ancestor <main最新commit> HEAD && echo OK`
2. 索引：`python -m scripts.verify_index --config config.json` **零改动全绿**
   （块数 20099／篇数 718／审计公告零泄漏）
3. embedding：`test -f /opt/yueceshao/models/Qwen3-Embedding-0.6B/model.safetensors && echo OK`
4. reranker：`test -f models/bge-reranker-v2-m3/model.safetensors && echo OK`
5. LLM key：分发文档 §三第 5 条的最小调用一行（回显 OK 才继续）

## 3 安装与 systemd 落位

```bash
cd /opt/yueceshao/yueceshao
python3 -m venv /opt/yueceshao/venv
/opt/yueceshao/venv/bin/pip install -r requirements.txt   # 含 uvicorn/torch 系
sudo cp deploy/yueceshao-api.service /etc/systemd/system/
sudo mkdir -p /etc/yueceshao && sudo vim /etc/yueceshao/yueceshao.env   # 0600，写 key
sudo systemctl daemon-reload && sudo systemctl enable --now yueceshao-api
journalctl -u yueceshao-api -f          # 看冷启动
curl -s http://127.0.0.1:8000/health    # 期待 real-retrieval-qwen-llm + index_chunks=20099
```

**两条硬约束（unit 文件头有注释，复述于此）**：

1. **`--workers 1`**：任务表在进程内——多进程各自持有任务表，轮询 404。
   扩容前先把任务表外置（Redis），那是架构升级不是改数字。
2. **`--proxy-headers --forwarded-allow-from 127.0.0.1`**：nginx 反代下让
   `client.host` 反映真实客户端 IP（限流按 IP 计数的正确性依赖它）。

## 7 日常运维

- 日志：`journalctl -u yueceshao-api -f`（含限流拒绝/任务失败/清理日志）
- 重启：`systemctl restart yueceshao-api`——**任务表清零**（R2 取舍），
  轮询中的任务变 404，客户端重新提交；限流桶清零
- 更新：`git pull`（main）→ `pip install -r requirements.txt`（有变更时）
  → `systemctl restart`——重启前跑 §2 的 1/2 两条核验
- 姿态与免责/AI 标识：全部服务端注入（红线③执行点在 API worker），nginx
  只透传，**任何前端不得渲染未带标识的裸报告**

## 8 红线对照（部署场景）

1. 语料/索引/模型**不经 git**（§1 通道表）；服务器上的语料与 dev 同源 rsync；
2. key 只在 `/etc/yueceshao/yueceshao.env`（0600，仓库外）——unit 文件、
   config.json、小程序包都不是它的家；
3. 数据仓服务器只读（`git clone` 后**禁 push**，§8.6 通道 B 不变）；
4. 审计公告不进索引：verify_index 全绿（审计公告零泄漏）才允许上线；
5. AI 生成标识＋免责声明由服务端注入（红线级，2025-09 法规），部署不改变
   其执行点。
