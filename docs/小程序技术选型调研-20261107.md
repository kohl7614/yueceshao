# 小程序技术选型调研：uni-app 复用 FastAPI 后端的可行性（2026-11-07）

> **只调研不开发**。分支 `docs/miniprogram-feasibility` · AI 参与整理（联网检索核对至 2026-11-07，来源见文末；个别无法核实处已标注「推断」）。
> 结论供组长与队友决策；是否立项、何时立项由组长拍板。

## 结论先行

**可行，但有两个硬约束和一个时机建议。**

1. **推荐路线**：个人主体小程序（零认证费）＋ uni-app 把前端**重写为原生渲染页面**＋ FastAPI 后端直连（HTTPS＋备案域名）。年现金成本约 **300 元量级**（学生机＋.cn 域名＋免费档 LLM）。
2. **硬约束一（主体）**：`web-view` 嵌 H5 组件**不对个人主体开放**——想"零重写直接套壳现有静态页"就必须企业主体（微信认证 300 元/年）；个人主体只能走原生渲染路线。
3. **硬约束二（合规链）**：小程序 ICP 备案（免费，约 2–3 周）＋ 后端域名 ICP 备案，二者缺一不可；AI 生成的四段式报告按 2025-09-01 施行的《人工智能生成合成内容标识办法》需加显式＋隐式"AI 生成"标识。
4. **时机建议**：`app/`（FastAPI 管线组装）目前尚未落地（仓库内仅有空 `__init__.py`），小程序没有可复用的后端——**建议等 FastAPI 服务跑通后再立项小程序**，避免前端空转。

## 1. 小程序类目与资质

| 事项 | 事实（2026-11 核对） | 对粤策哨的含义 |
|---|---|---|
| 主体类型 | 个人主体注册免费（身份证实名）；企业/组织主体需微信认证 300 元/次·年审 | 个人主体够用（无支付需求）；成本敏感可选个人 |
| 个人主体限制 | **不可用 web-view 组件**；不可微信支付（仅试点虚拟支付，月限额 10 万且排除搜索/信息发布类） | 套壳路线对个人主体直接排除 |
| 类目选择 | 非个人主体「工具-信息查询」**无附加资质要求**（资质栏"/"） | 以"申报前自查辅助工具"申请工具类目 |
| 时政信息类目 | 需《互联网新闻信息服务许可证》＋属地网信部门首审约 7 天 | **学生团队无法获得**——界面与简介必须避开"时政/政务资讯/政策解读"表述，定位为工具 |
| 政务民生类目 | 仅对政府/事业单位或持政府授权文件者开放 | 不适用 |
| AI 内容标识 | 《人工智能生成合成内容标识办法》2025-03-14 发布、**2025-09-01 施行**：AI 生成内容须加显式＋隐式标识，分发平台须核验 | 四段式报告页需加"AI 生成"标识；与现有"姿态禁语＋免责声明"红线叠加，服务端渲染层统一注入即可 |
| 小程序备案 | 2023-09 起新小程序**须先完成 ICP 备案才能发布**；免费；材料为身份证（个人）；平台初审 1–2 天＋工信部短信核验＋管局 1–20 个工作日；**不要求先有域名/服务器** | 立项后立即启动备案（周期最长，是关键路径） |

## 2. web-view vs 原生（uni-app）

| 方案 | 可行性 | 说明 |
|---|---|---|
| web-view 套壳现有静态页 | 仅企业主体 | 需业务域名（HTTPS＋备案＋域名根目录放校验文件）＋微信认证；`@message` 通信触发时机受限。个人主体**不可用** |
| uni-app 原生渲染 | ✅ 推荐 | Vue 模板编译为 WXML/WXSS（每个 .vue → 同名 js/json/wxml/wxss 四文件）；一套代码可同时出微信小程序＋H5，为将来多端留口 |
| 原生小程序 | 备选 | 单端性能与 API 支持最优，但只服务微信一端 |
| Taro | 备选 | React 生态（34k+ star，京东维护）；Taro3 运行时方案性能略逊 uni-app 编译方案 |

**现有 demo 的复用成本**：demo 是纯 HTML＋CSS＋JS（非 Vue），**不能直接当 uni-app 页面用**——模板、路由（pages.json）、样式适配需重写为 Vue 页面；但 `js/data.js`（预置案例与静态报告数据）与 `js/app.js` 的渲染逻辑可作为 JS 模块迁移，语义层复用度高，视觉层需按小程序组件重写。**推断**：重写量约为"新写一个小程序前端、数据层与文案层照搬"，不属于一次性抛弃式成本。

uni-app 维护现状：DCloud 持续维护；新一代 **uni-app x**（UTS 语言＋原生渲染）与经典 uni-app（Vue）并行，经典线仍维护。

## 3. 后端 API 需哪些改动（FastAPI，设计约束清单）

> `app/` 尚未实现，以下作为将来 app/ 设计时的约束，而非改造存量代码。

1. **不需要 CORS**：`wx.request`/`uni.request` 跑在非浏览器环境，无同源策略——FastAPI 无需配 CORS 中间件（只有 web-view 套壳方案才需要）；
2. **必须 HTTPS＋已备案域名**：request 合法域名要求 ICP 备案（新备案约 24h 后可配）；域名上限 20 个、**每月可修改 50 次**——域名变更要谨慎；
3. **接口形态**：`POST /api/check`（项目描述 → 四段报告 JSON）。注意 reranker 在 CPU 上为秒级/条（本仓标定实测：40 条查询×40 候选 CPU 约 15 分钟），线上 60 秒请求超时内跑不完完整管线——**建议异步任务＋轮询（或 SSE 不适用小程序，用轮询）**，接口拆 `提交体检 → 查询结果` 两个；
4. **密钥永不进小程序包**：LLM API key 只存服务端环境变量（现行红线不变；小程序包是可被解包的公开物）；
5. **registry 服务化**：文号注册表从本地 SQLite/JSON 变为服务端读取，供引用校验器与渲染层注入（文号仍由块元数据模板注入，LLM 不手打——架构三条结构性判断原样成立）；
6. **限流与防滥用**：公开访问的体检接口需限流（防 LLM 费用被刷穿）；
7. **姿态禁语＋免责声明＋AI 标识**：全部由服务端渲染层强制注入，客户端只展示（红线③的执行点从"渲染层"平移到"服务端渲染层"）。

## 5. 风险与红线映射

| 风险 | 对策 |
|---|---|
| 审核：内容被归入"时政信息" | 类目走"工具-信息查询"；名称/简介/页面文案避开"政策解读/政务资讯"，统一"申报前自查辅助"口径（与现有免责声明一致） |
| AI 标识新规 | 服务端渲染层注入显式"AI 生成"标识（与免责声明同点位） |
| 结论性措辞 | 现有姿态禁语红线原样适用；校验器兜底在服务端 |
| 数据泄露 | 审计公告出题集不进检索索引（红线④）照旧；标注表等数据文件不进小程序包与代码仓库 |
| 密钥泄露 | key 只在服务端；`.env`/config.json 不入库照旧 |
| 演示一致性 | 小程序预置案例与 web demo 同源（同一份 registry 真实文号），避免两套事实 |
