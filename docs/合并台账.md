# 合并台账（分级委托合并的留痕，随 PR 审查）

> **用途**：分级委托合并的审计台账。**漏记视同违规**；负责人不定期抽查。
> **本文件是唯一的正式台账**（2026-11-06 由团队工作区 `06_过程档案/合并台账-harness.md` 迁入代码仓）：放进仓库的好处是——随 PR 一起被审查、任何人 clone 就能看到、`git log`/`git blame` 天然留痕；明细过程记录仍可留在团队工作区的过程档案里，但**以本文件为准**。
> **更新方式**：随任意一次 PR 一并提交（**允许滞后一次合入**：PR X 的台账行若未赶上 PR X 本身，必须在**下一个** PR 内补记，否则视同漏记）。PR X 的台账行必须在合并后按真实结果填写（三验通过、拿到 merge commit sha 才写）。
> **通道与授权**：见 `docs/AI协作开发规范.md` §8。
> **授权代审留痕（§8.2，2026-11-06 拍板口径）**：通道 B 终审权归负责人；本表内由代理/独立会话代审合入的通道 B 行，授权原话与日期如下——#40/#41「两个 PR 待你终审合并…建议先合 #40，再合 #41」（2026-11-06）；#43「可以，你开第二轮」→ 独立会话终审（2026-11-06）；#44「开收窄 PR」→ 独立会话终审（2026-11-06）；#47「等会让你来终审」→ 代理终审（2026-11-06）；#49 属通道 A 的 docs PR，合入＝独立会话（2026-11-06）。**一次授权仅覆盖被点名的 PR 与当轮，不可复用。**
