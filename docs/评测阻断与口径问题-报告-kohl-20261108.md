## 2. P0-1：`--pipeline real` 在 main `9416a8b`/`1704350` 上直接崩（阻断四人）

## 4. P0-3：标注说明文字被当成"期望条款"（73 个，污染召回分母）

**事实**：`eval/dataset.py:105` 的过滤只认 `不覆盖本情形` / `不覆盖此情形` 两种写法，
而标注列里实际还有这些写法，全部被 `REF_EXTRACT_PATTERN` 当成「文号#条款号」解析出来：

```
106号第十八条不覆盖（用地合规属自然资源政策口径）
106号第十八条不覆盖（保险保费补贴规则属政策性农业保险条款域）
知识库暂无对应政策文件，建议补采设施农业用地管理规定
属政府采购与招投标法规域，知识库暂无对应文件
库内暂无对应文件
```

**后果**：这些"期望条款"永远不可能命中，直接把召回压到 0；`group_details.csv` 的
`expected_refs` 列里能直接看到它们。

**修复**：只接受「文号在 `eval/registry-export.json` 里存在 且 条号可解析」的引用为正例；
其余落成结构化字段（`口径外` / `库内缺口`），**不计入分母但单列报数，不隐藏**。

## 5. P0-4：79 个真期望条款 100% 指向 `粤财农〔2020〕106号`，而语料判定它已失效

这是召回为 0 的第二重原因，也是**必须由负责人裁定**的一条。

| 查证点 | 实测结果 |
|---|---|
| 全表真引用去重文号 | **只有 1 个**：`粤财农〔2020〕106号`（79/79） |
| 该文号在索引里的 `validity` | **`已失效`**（`publish_date=2020-08-24`，标题《广东省涉农资金统筹整合管理办法（2020年修订）》） |
| 该文号在负面清单里 | 15 条记录，**全部 `active=False` / `effective=False`**（标注为“建议人工归并”“锚词组（建议稿，人工裁定）”）；标注最常指望的**第二十条不在清单里** |
| 时效过滤开 → 36 条中检索到 106 号 | **0 / 36** |
| 时效过滤关 → 36 条中检索到 106 号 | **3 / 36** |

**解读**：系统拒引失效文件是**设计正确**；标注回填的是当年审计适用的历史条款。
两者不冲突是不可能的——除非裁定「回溯评测该以历史时点为准」或「期望条款应指向现行替代文件」。

**与 `docs/评测口径.md` 的关系**：该文档已把召回收窄为「禁止用途正例」并把
“库内暂无”标 `未覆盖`，方向与本报告一致。本报告补充的是**实现层证据**：
106 号不是“没标好”，是**语料判它失效 + 清单未激活它**，所以任何模型/调参都救不回召回。

**待裁定**（见 §7）：106 号是否真被废止？若真废止，79 条期望条款要重定向到哪份现行文件？

## 6. P1 / P2：不修会继续污染指标的四条

### P1-1：`parse_node` 无重试，一条坏 JSON 打挂整批
`app/graph.py:156-158` 直接 `parse_extraction`，`SchemaError` 直穿整条管线。

### P2-1：词典泛词误命中（匹配率虚高的直接原因）
匹配口径是「描述侧词 与 条款侧词 落同一概念组即命中」，于是一个泛词打开一大片：

- **实测**：C03 描述出现「车辆」→ 命中 **34 条**条款，命中词 `车辆 → 交通工具/通讯设备`，
  引用为 `开府办〔2026〕12号#16`、`汕工信规字〔2026〕1号#27`、`惠市工信〔2026〕115号#29` …
  与标注期望的 106 号毫无关系；
- **实测**：前 36 条规则命中的案例 20 条，其引用与期望条款**交集 0/36**；
  即 `匹配 55.56%`（已跑完的 full 组）**全部来自误报**，不是真命中。

**修复方向**（本窗口在做的）：词典分强弱词——强词（挪用/截留/套取/化整为零/串通投标/
坐支/私存/白头单/侵占/私分/虚报/冒领…）单独即命中；弱词（车辆/补贴/工资/教育/医疗/
补助/津贴/奖金/借款/担保/绿化/苗木/景观/建设用地…）需「弱词＋违规语境」或跨组共现才命中。
验收用**全 142 条 + 14 条负对照（C148–C161）**做确定性回归（规则引擎不花 token）。

### P2-2：33.9% 的索引块没有文号
索引 20,100 块中 6,637 块 `doc_no = 无（页面未载/仅正文引用，不计）`。
这类块进不了引用核验，是 `引用错误率 38.89%` 的主要来源。
**归属**：语料层（数据仓）历史页面无文号，系统侧只能选择"不拿它做引用"，
不能靠改指标掩盖。

### P2-3：检索对期望文号几乎无召回
即便关掉时效过滤，36 条里也只有 3 条能检索到 106 号；**用 106 号第二十条原文去检索，
它自己都排不进前 10**（该块与查询余弦 0.808，但同查询下别的文件更高）。
说明检索排序对这类"管理办法正文"偏弱，属检索课题（chunk/指令/混合检索/rerank），
**建议等 §7 裁定后再决定是否投入**。

## 11. 已知限制登记（裁定 4 · 2026-11-09）

### L1｜106号#18 第(一)项类条款无词典锚点，规则引擎结构性命不中

**现象**：`粤财农〔2020〕106号` 第十八条第（一）项「行政事业单位基本支出」、第（十一）项
「其他非涉农领域支出（兜底）」等条款文本为**纯描述性表述**，不含任何禁止用途词典概念词
（如"奖金津贴""楼堂馆所""偿还债务"）。规则引擎的匹配口径是「描述侧词 ↔ 条款侧词落同一概念组」，
故这类条款**无论描述怎么写都不可能被规则命中**——属结构性限制，非调参可解。

**影响范围**（已实测）：本片 C42（违规提取工作经费）、C23/C41（违规采购）、C73/C105/C110/
C114/C116/C117/C122/C126/C128/C130/C134 等 16 条同型案例，全部如实留 miss。

**处置**：
1. 本轮**不扩②段射程、不改①②段判定逻辑**，这些案例留在②段分母内作为真实 miss（裁定 4 选 c）；
2. 归并库补锚点（给这类条款人工标注概念锚词）列入**词表扩充工作包**；
3. 补锚点后按《词典边界与判据》三判据（误报面/边际召回/规则可达性）出**负对照 0 误报证据**，
   再跑 `python -m eval.reevaluate` 即可**免费翻绿**，不必重跑 LLM。

### L6｜序号 162 审计报告类别标错 → 49 块审计内容在索引内（红线④数据层渗漏）

**事实**（负责人裁定接受登记）：数据仓序号 162 的审计报告在 registry 中类别标错，导致其
**49 个块进入检索索引**，占全库 **0.24%**（49/20100）。`exclude_categories` 是**元数据层**
过滤，类别标错的块拦不住——属**数据层渗漏**，非代码可解。

**影响**：这些块若被引用，因 `eval/registry-export.json`（由规则库导出）无对应条目，
会被计为**引用错误**——这是指标对数据缺陷的**诚实受罚**，不做豁免、不做静默剔除。

**真正修复路径**：① 数据仓把序号 162 的类别改判（不属审计公告）；② 下次索引重建时出清这 49 块。
两项均列入**迭代工作包**，不在本评测窗口处理。


### L7｜索引交接纪律（正本采信的硬性前提）

**块数一致不构成内容一致的证据。** 采信一份索引为正本，必须同时拿到**索引交接三件套**：

1. **入库时间**（索引构建完成时刻）；
2. **数据仓语料 commit**（构建时所用语料的 git commit）；
3. **rag 代码 commit**（构建时所用切块/嵌入代码的 git commit）。

缺任一项，块数相同也可能内容不同（清洗口径、切块器版本、语料快照任一变化都会改变块内容），
不可作为跨分片可比基线。本次 20099 与 20100 的差异正是「内容差异被块数掩盖」的反例：
两边块数只差 1，但差的那块是**清洗失败的空壳**，性质完全不同。
